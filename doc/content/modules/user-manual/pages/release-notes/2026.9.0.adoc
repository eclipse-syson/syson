= 2026.9.0 (work in progress)

== Key highlights

* `Requirement` derivations are now displayed as `«derive»` edges in _General View_ diagrams and can be created directly from a diagram.
* Diagrams now display a broader range of inherited elements, including requirements, concerns, constraints, actors, subjects, items, and action parameters.
* `PartUsage` and `PartDefinition` graphical nodes now include _requirements_ and _concerns_ compartments, with tools to create elements in them.
* The _Requirements table_ view now displays nested requirements hierarchically and provides an action to create nested requirements.
* {product} Docker images now run natively on both `linux/amd64` and `linux/arm64` platforms.

** `Requirement` derivations are now displayed as edges in _General View_ diagrams.
A `Requirement` derivation records that a `Requirement` has been derived from another `Requirement`, allowing a detailed `Requirement` to be traced back to its source.
+
The edge goes from the derived `Requirement` to the original `Requirement` and is displayed as a dashed line labelled `«derive»`, distinguishing it from a `«satisfy»` edge.
+
image::release-notes-requirement-derivation-edge.png[Requirement derivation displayed as an edge in a General View diagram]
+
`Requirement` derivations can be created from SysML v2 text by using either the _Upload model_ action or the _New objects from text_ action in the _Explorer_.
The following text creates two requirements and a derivation between them:
+
[source,sysml]
----
private import RequirementDerivation::*;
requirement article5Compliance;
requirement paymentDelayPrevention;
#derivation connection {
    end #original ::> article5Compliance;
    end #derive ::> paymentDelayPrevention;
}
----
+
Once both requirements are displayed in a _General View_ diagram, for example by dropping them from the _Explorer_, the `«derive»` edge between them appears automatically.
The `#original` and `#derive` metadata on the edge ends determine its direction, so the declaration order of the ends has no effect.
** `Requirement` derivations can now be created in a _General View_ diagram with the _New Derived Requirement_ edge tool available on `RequirementUsage` graphical nodes.
+
The edge is drawn from the derived `Requirement` to the original `Requirement`, which is the direction in which the derivation is read: _this requirement is derived from that one_.
+
image::release-notes-new-derived-requirement-tool.png[New Derived Requirement edge tool on RequirementUsage graphical nodes, width=60%,height=60%]
+
A derivation created with the edge tool is equivalent to one written in text, so both can be used in the same model.
Exporting the model produces the `#derivation` connection shown above.
The `RequirementDerivation` library is imported automatically when the model does not already import it.

== Bug fixes

* In diagrams:

** Fix nested-usage edge tools in _General View_ diagrams.
The connector palette now provides one type-specific tool for a Usage target: _Add target as nested <type>_ from a Usage source, or _Add target as owned <type>_ from a Definition source.
No such tool is proposed for non-Usage targets, and _Become nested <type>_ remains specific to the source usage kind.
** Fix the missing graphical edge between `ConcernUsage` or `ConcernDefinition` graphical nodes and the actors created from them.
** Fix the nested composition edge tool label on `ConcernUsage` graphical nodes in _General View_ diagrams.
It is now _Become nested Concern_ instead of _Become nested Requirement_.
** Fix inherited `PortUsage` ends in the _ends_ compartment of `InterfaceDefinition` graphical nodes.
** Fix unresolved connection ends declared with the `end` keyword inside a connection body.
The affected connections were missing their source and target and were therefore never displayed as edges.
** Fix an issue that prevented a nested `AttributeUsage` from becoming visible when it was first dropped from the _Explorer_ onto a _General View_ diagram.
** Fix `Comment` graphical nodes so changing their background color no longer changes their border color.
** Rename the _New Perform action_ tool to _New Perform Action_ for consistency with other tools.
** Remove the _New Subclassification_ edge tool from `EnumerationDefinition` graphical nodes, which cannot subclassify another `EnumerationDefinition`.

* In all views:

** Fix expression creation and editing on `SuccessionAsUsage` elements.
** Fix the _Typed by_ property in the _Details_ view so that a `Usage` can only be typed by the corresponding kind of `Definition`.

* In textual import/export:

** Fix the export of the keywords carried by the ends of a connection, such as the `#original` and `#derive` of a `Requirement` derivation, which were missing from the exported text when the connection had been created from a diagram.
Exporting such a connection and importing it back no longer loses which end is which.
** Fix the import of `TransitionUsage` using _start_ which now set the source to the `StateUsage` _start_ from the standard library instead of `ActionUsage` _start_ from the standard library.

** Fix the export of a documentation, a comment or a textual representation whose text contains `*/`.
That sequence closes a comment in the SysML v2 textual notation, so the exported file could no longer be read.
It is now exported as `* /`, and a warning reports it, since the exported text is then not exactly the one that was written.
** Preserve cross-document references when a SysML document is uploaded with a directory in its filename.

* In validation:

** Prevent AQL parser failures when loading the built-in SysML validation rules.

== Improvements

* In diagrams:

** When selecting multiple graphical nodes, the group palette now displays the _Show/Hide_ section just like the single selection palette.
The associated tools are the same ones: _Hide_; _Hide all content_; _Show all content_; _Reset content_; _Show valued content_.
+
image::release-notes-show-hide-section-group-palette.png[New Show/Hide section in group palette, width=90%,height=90%]

** In standard diagrams, the group palette now provides _Delete from diagram_ when multiple graphical nodes are selected.
It removes all selected nodes from the diagram without deleting the corresponding model elements.

** Selection dialog trees now apply the default _Explorer_ filters, hiding `Memberships`, root `Namespaces`, expose elements, and expression internals.
It allows to focus on the elements that are relevant for the current model, while still allowing to select library elements.

** Direct edit no longer parses or modifies expressions.
Use the dedicated expression tools to create or modify expressions, while direct edit remains focused on labels and feature syntax.

* In _Details_ view:

** In reference widget model-browser dialogs, `Memberships` and root `Namespaces` are now hidden, making models and standard libraries easier to navigate.
It allows to focus on the elements that are relevant for the current model, while still allowing to select library elements.
It also makes it consistent with the _Explorer_ view, which already hides `Memberships` and root `Namespaces`.
