== Manage elements

=== Create element

Users can create elements **from the diagram background** by right-clicking to display the palette.
In this palette, element creation tool are grouped by type in tool sections according to their type.
Users can click a tool section and then select the desired creation tool.

image::manage-elements-fromBackground-creation.png[Creation from Diagram Background]

Inside a tool section (for example the Structure tool section):

image::manage-elements-fromBackground-creation-2.png[Creation from Diagram Background]

The palette has a search field allowing to search in all tool sections.

image::manage-elements-creation-search.png[Creation search, width=30%,height=30%]

Users can also create elements **inside other elements**.
User just right-clicks on the element to display the palette and then click on the desired creation tool.

image::manage-elements-fromElement-creation.png[Creation from Diagram Element, width=70%,height=70%]

All created elements are collapsed by default. This means that when a node with compartments is created, its compartments are hidden.

If a node contains **compartments**, users can add an element to the desired compartment by right-clicking the compartment to display the palette.

image::manage-elements-fromCompartment-creation.png[Creation from Compartment, width=70%,height=70%]

Another way is to right-click the parent node header of the compartment.
The palette is displayed, and users can select the desired creation tool from a tool section. The new element is created in the appropriate compartment.

image::manage-elements-fromParentCompartment-creation.png[Creation from Parent Compartment, width=70%,height=70%]

=== Redefine a nested feature

The _Redefine a nested feature_ tool allows users to customize an inherited feature within a specific _Usage_ or _Definition_, including features nested several levels deep.
The original features remain unchanged.

Consider the following model:

image::redefine-nested-feature-model.png[Example model, width=70%, align=center]

The `vehicle` part inherits the `engine` part from `Vehicle`, and `engine` provides the `power` attribute through its `Engine` definition.
To customize `power` for this vehicle, users can redefine the `engine.power` feature chain directly from the `vehicle` node.

To redefine a nested feature:

. Right-click the `vehicle` node to open its palette.
. In the _Structure_ section, select _Redefine a nested feature_.
. In the dialog, select `engine.power`.
. Confirm the selection.

image::redefine-nested-feature-dialog.png[Feature selection dialog, width=80%, align=center]

{product} creates the local redefinitions needed along the selected path.
Existing local features or redefinitions are reused.

In the example above, the tool creates a local redefinition of `engine` inside `vehicle`, then a local redefinition of `power` inside that engine.
If `engine` is already locally redefined, only the missing redefinition of `power` is created.

The last feature in the resulting chain is selected and revealed in the Model Explorer.
Users can then edit its properties in the Details view.

image::redefine-nested-feature-result.png[Redefine result, width=70%, align=center]

[NOTE]
====
The dialog lists accessible feature chains that still require at least one local redefinition.
Features declared in the SysML and KerML standard libraries are excluded.
Fully local chains are no longer listed.
====

=== Delete element

Users can delete a graphical element from the diagram without removing it from the model.
Click the _Delete from diagram_ button in the palette.

image::manage-elements-delete-from-diagram.png[Delete from diagram, width=70%,height=70%]

Users can also remove an element from the model (and therefore from the diagram) by clicking the _Delete from model_ button in the palette.

image::manage-elements-delete-from-model.png[Delete from model, width=70%,height=70%]

A confirmation dialog appears when an element is deleted via the _Delete from model_ tool in the palette or via the Model Explorer.
This behavior can be disabled by checking the "Disable this confirmation dialog" checkbox in the dialog.

image::manage-elements-semantic-deletion.png[Semantic Deletion]

[TIP]
====
This preference is stored in the local storage of the browser.
You can reset it by deleting the {product} data in cache of your browser.
====

=== Duplicate Element

Users can duplicate an `Element` and its representation node by clicking the _Duplicate Element_ button in the palette.

image::manage-elements-duplicate-from-diagram.png[Duplicate element from Diagram]

=== SysON Theme

include::user-manual:partial$before-you-start-experimental-all.adoc[]

A theme can be enabled for a project from the _Appearances_ tab in the project settings.
The theme customizes the color of graphical elements according to their SysML element family (Structure, Behavior, ...).

You can still change colors through the _Appearance_ section of the palette.
These changes take priority over the SysON theme.
When the theme is enabled, resetting manual appearance changes restores the SysON theme if it is enabled.
